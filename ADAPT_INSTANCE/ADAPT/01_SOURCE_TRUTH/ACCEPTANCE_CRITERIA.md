# Acceptance Criteria

SourceTruthVersion: SOURCE_TRUTH_V0.1
Status: ACCEPTED_BUSINESS_CRITERIA

| ID | Criterion |
|---|---|
| AC-001 | A resident can create a job request. |
| AC-002 | A worker can see nearby open jobs using safe discovery data. |
| AC-003 | A resident can see nearby workers and factual trust signals. |
| AC-004 | Barangay staff can create a job request for a resident. |
| AC-005 | Barangay staff can register or view a worker. |
| AC-006 | The Quest board can show open jobs without exposing private resident data. |
| AC-007 | A worker can respond to a job request. |
| AC-008 | A resident can accept one worker response and create a match. |
| AC-009 | Exact address and contact details are hidden before match. |
| AC-010 | Coordination details are available only to the matched resident and worker. |
| AC-011 | A matched job can be completed once. |
| AC-012 | A resident can leave a rating and review after completion. |
| AC-013 | Completed work updates simple worker reputation indicators. |
| AC-014 | Mobile and Quest flows share the same local labor records. |
| AC-015 | Trust and barangay labels do not imply guaranteed quality or legal certification. |
| AC-016 | The product can be explained clearly to residents, workers, barangay staff, and partners. |
