# Acceptance Criteria

| ID | Criterion | Status |
|---|---|---|
| AC-001 | A resident can create a job request. | ACCEPTED |
| AC-002 | A worker can see nearby jobs. | ACCEPTED |
| AC-003 | A resident can see nearby workers. | ACCEPTED |
| AC-004 | Barangay staff can create a job for a resident. | ACCEPTED |
| AC-005 | Barangay staff can register or view a worker. | ACCEPTED |
| AC-006 | The quest board shows open jobs. | ACCEPTED |
| AC-007 | A worker can respond to a job. | ACCEPTED |
| AC-008 | A resident can accept one worker. | ACCEPTED |
| AC-009 | Exact address and contact details are not exposed before match. | ACCEPTED |
| AC-010 | A matched job can be completed without duplicate completion. | ACCEPTED |
| AC-011 | A resident can leave a review after completion. | ACCEPTED |
| AC-012 | Completed work updates worker reputation. | ACCEPTED |
| AC-013 | Mobile and Quest flows remain connected. | ACCEPTED |
| AC-014 | The product can be explained clearly to residents, workers, barangay staff, and partners. | ACCEPTED |

These are business acceptance criteria. Executable test cases have not been designed.
