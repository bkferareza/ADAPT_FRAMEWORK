## Inferred Project Shape

- Project name: Paggawa: Local Skills Discovery and Barangay-Assisted Job Matching Platform
- Business/domain: Local skilled-labor discovery, trust signals, privacy-aware matching, and barangay-assisted access.
- Primary users: Residents/clients, skilled workers, barangay staff, and a possible future referrer role.
- Main workflows: Create request, discover jobs/workers, barangay-assisted request/registration, worker response, resident acceptance, private coordination, completion, review, and reputation.
- Suggested surfaces/modules: Paggawa Mobile, Paggawa Quest, identity/actor access, worker registry, job requests, discovery, responses, matches, completion, reviews/reputation, barangay notes, privacy/trust policy.
- Suggested workcell types: Director/Source Truth, Backend or domain/data, Mobile Frontend, Quest Frontend, Integrator, independent QA, and optional privacy/trust Challenge review.
- Validation concerns: Pre-match privacy, matched-party authorization, status transitions, one accepted response, idempotent completion, review eligibility, reputation updates, trust wording, barangay permissions, and Mobile/Quest consistency.
- Integration concerns: Shared cross-surface records, privacy unlock rules, actor permissions, status semantics, response-to-match behavior, review/reputation propagation, and future backend migration boundaries.
